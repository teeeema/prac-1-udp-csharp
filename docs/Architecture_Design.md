# Проектирование архитектуры

## Назначение

Проект моделирует минимальную сетевую часть многопользовательской игры. Клиент отправляет игровые команды по UDP, а отдельный сервер проверяет их, изменяет авторитетное состояние игрока и возвращает подтверждённое состояние.

Реализация написана на C# и .NET 10. Для UDP используется стандартный класс `System.Net.Sockets.UdpClient`.

## Выбранная топология

Используется **Dedicated Server**: сервер запускается отдельным процессом и не является игровым клиентом.

Причины выбора:

- сервер является одной авторитетной стороной;
- клиент не подтверждает координаты или результат выстрела самостоятельно;
- состояние не зависит от жизненного цикла одного из игроков, как в Listen Server;
- клиенты не должны соединяться друг с другом, как в P2P;
- сервер может хранить отдельное состояние для каждого IP:port.

Для локальной проверки клиент подключается к `127.0.0.1:27015`, а сервер слушает UDP-порт `27015`.

## Обязанности клиента

- формировать `MOVEMENT` и `SHOOT`;
- назначать каждой команде `UInt16 SequenceNumber`;
- сериализовать команду в бинарный пакет;
- периодически отправлять UDP-дейтаграммы;
- принимать `STATE_UPDATE`;
- проверять `SequenceNumber` ответа;
- выводить подтверждённое сервером состояние.

## Обязанности сервера

- слушать UDP-порт через `UdpClient`;
- принимать дейтаграммы;
- десериализовать и проверять заголовок и payload;
- хранить отдельный `ClientState` для каждого адреса клиента;
- принимать координаты только в диапазоне `[-1000; 1000]`;
- принимать `weaponId` только от 1 до 3;
- применять допустимые команды и не менять состояние при отклонённых командах;
- отвечать `STATE_UPDATE` с тем же `SequenceNumber`;
- писать команды в консоль и `server.log`.

```text
┌────────────────────────┐                 ┌──────────────────────────┐
│ UdpGame.Client         │                 │ UdpGame.Server           │
│                        │                 │                          │
│ Movement / Shoot       │                 │ UdpClient.Receive()      │
│        │               │                 │        │                 │
│        v               │                 │        v                 │
│ ProtocolSerializer     │ -- UDP -------> │ ProtocolSerializer       │
│        ^               │  MOVEMENT/SHOOT │        │                 │
│        │               │                 │        v                 │
│ STATE_UPDATE check     │ <-------------  │ Validation + ClientState │
│        │               │  STATE_UPDATE   │        │                 │
│        v               │                 │        v                 │
│ Console                │                 │ Console + server.log     │

```

## Последовательность одной команды

1. Клиент увеличивает `SequenceNumber`.
2. `ProtocolSerializer` создаёт бинарный `MOVEMENT` или `SHOOT`.
3. `UdpClient.Send()` отправляет одну UDP-дейтаграмму.
4. Сервер получает её через `UdpClient.Receive()`.
5. Сервер вызывает `ProtocolSerializer.Deserialize()` и проверяет данные.
6. Сервер обновляет `ClientState`, если команда допустима.
7. Сервер создаёт `STATE_UPDATE` с тем же `SequenceNumber`.
8. Клиент принимает ответ, десериализует его и проверяет номер запроса.

UDP не гарантирует доставку и порядок. Учебный клиент использует тайм-аут и `SequenceNumber`, но не выполняет повторную отправку.
